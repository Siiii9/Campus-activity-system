## 4. 配置管理过程
**（由 sunbo 写）**

### 4.1 配置项识别
识别出的主要配置项包括：
| 配置项 | 文件名 | 责任人 |
|--------|--------|--------|
| 项目章程 | 01-project-charter.md | 全体 |
| WBS文档 | 02-wbs.md | zhangdongze |
| 进度计划 | 03-schedule.md | zhangdongze |
| 配置管理方案 | 04-config-plan.md | sunbo |
| 总结报告 | 05-summary-report.md | 全体 |
| 冲突演练文件 | conflict.md | chenjingpeng |

### 4.2 分支策略
main # 最终提交分支（受保护）
└── dev # 开发集成分支
├── feature/config-plan # 配置管理分支
├── feature/plan # 计划分支（WBS+进度）
└── feature/conflict # 冲突演练分支

### 4.3 提交规范
格式：`<类型>: <描述>`
- docs：文档更新
- feat：新功能
- fix：问题修复
- chore：初始化/配置

### 4.4 合并规则
1. 所有功能分支从 dev 创建
2. 完成后向 dev 发起 Pull Request
3. PR 需至少1人审核
4. 由项目经理负责合并
5. 最终统一从 dev 合并到 main
